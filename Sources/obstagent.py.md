## *Stable section*
### *Purpose*
*Последовательный наблюдатель [[Glossary/obstagent]]: превращает сигналы пользователя в вызовы исполнителя и сохраняет историю А/Б. Пользователь работает через заметки по [[Scenarios/001-mvp]]. Управление пользовательскими ветками Git и защита remote находятся вне ответственности файла.*
## *Specification and scope*
*Реализовать наблюдение за заметками, обработку сигналов, последовательный запуск исполнителя и сохранение/восстановление А/Б по следующим требованиям.*
*Настройки и их переопределение — [[Conventions/Конфигурирование obsta]]. Сигналы — [[Conventions/Сигналы активации]], границы и оформление — [[Conventions/Тикеты]], цикл — [[Scenarios/001-mvp]], история и восстановление — [[Conventions/Использование Git#Действующий договор версии 1]]. Это ссылки на требования для пересоздания блока.*
*Один файл `Sources/obstagent.py`, включая встроенные проверки. Обёртка `Sources/obstagent.sh` — внешний потребитель. Путь и форму блока менять только по решению пользователя. Управление пользовательскими ветками Git и защита remote находятся вне границы блока.*
### *Interface*
*CLI: `--vault` (по умолчанию корень над Sources), `--interval` (0.5 с), `--settle` (1 с), `--timeout` (1800 с), `--once` (два прохода наблюдения), `--self-test` (ограниченная проверка перезапуска), `--self-test-full` (все регрессии). interval и timeout положительны, settle неотрицателен. Выход: 0 — штатное завершение/успешные тесты, 1 — ошибка запуска/тестов, 2 — неверные аргументы, 75 — запрос перезапуска обёрткой.*
*Исполнитель запускается из корня vault: новый `codex exec --json`, продолжение `exec resume --json`, дочерняя ветка `exec fork --json`; политика approval_policy=never. Вход — [[Conventions/Agent Instruction]] и runtime JSON по [[Conventions/Протокол работы с агентом-исполнителем]], плюс повторяемое при каждом вызове правило сохранения человеческого текста и оформления предложений. Финал — JSON с outcome=success/error и строкой response; ошибка, неполный JSONL, неподтверждённая сессия или отсутствие turn.completed означают неуспех. Публичные agent_message обновляют статус; reasoning скрыт. При таймауте завершается группа процессов исполнителя.*
*Хранилище должно быть корнем Git-репозитория. Совместимость сохранённых данных: история версии 1, старые числовые и новые именные ID с дочерними компонентами; старые служебные маркеры в HTML-комментариях и двойных процентах читаются. Новые заметки не получают служебных маркеров активации: привязка результата к запросу хранится как request_length и SHA-256 request_hash префикса тикета, включая пробел после открывающей границы; сохраняется также fork_parent_session_id. Потеря кэша до А без однозначных данных требует явной реактивации.*
### *Additional requirements*
*Python 3.9+, POSIX (flock, ps, группы процессов), Git; для реальной работы Codex с JSON exec/resume и fork для дочерних тикетов. Один наблюдатель на общий Git-каталог. SQLite не читается и не удаляется. HEAD и пользовательский индекс сохраняются; служебное состояние находится внутри Git. Условия обновления и код 75 — [[Conventions/Запуск и перезапуск obstagent]].*
*Обрабатывать Markdown после периода стабильности; не обходить скрытые каталоги и символические ссылки, исключить саму инструкцию исполнителя. Кодовые блоки, inline code, HTML- и Obsidian-комментарии не дают сигналов или границ. Неверные, повторные и пересекающиеся границы диагностировать. Соседние жирные фрагменты, разделённые только пробелами, составляют один запрос.*
*В конце тикета продолжать подтверждённую сессию; внутри — создавать дочернюю через fork. При отсутствии сессии или поддержки fork сохранять сигнал. Снятый чек-лист остаётся на отдельной строке с исходным отступом; дочерние строки входят в тикет. Обновлять только собственный точный фрагмент статуса, сохранять человеческие правки и рабочие ссылки Obsidian. Удалённые заметки/границы не восстанавливать.*

### *Acceptance*
*В отдельном временном Git-репозитории с настроенным автором, Configs/obsta.md, непустой инструкцией и тестовыми заметками проверить цикл А → исполнитель → ответ → Б; неизменность HEAD/индекса; игнорирование файлов и Sources; уникальность ID после удаления заметок; fork/resume; чек-лист с новой строки; сохранение конкурентных правок. Использовать управляемый поддельный Codex с JSONL, без реальных запросов модели.*
*Проверить отказы каждого этапа Git, конфликт ref, потерю кэшей и аварии вокруг А/Б: без А нет исполнения, завершённое не повторяется, неизвестный исход требует сигнала, живой исполнитель удерживает очередь, ошибка Б повторяет только сохранение, ошибка одного запроса не останавливает наблюдение. Проверить таймаут/ошибки JSONL и перезапуск только для сохранённого в Б неизменного исходника после успешного self-test за 60 с. Команды из корня: `python3 Sources/obstagent.py --self-test` и `python3 Sources/obstagent.py --self-test-full`. При пересоздании эти проверки нужно реализовать заново по требованиям.*
## *Volatile section*
### *Files*
*[[Sources/obstagent.py]] — реализация и unittest. [[Sources/obstagent.sh]] — внешняя обёртка для повторного запуска после 75, вне границы блока.*
### *Implementation details*
*History.snapshot использует отдельный индекс, commit-tree и условный update-ref с тремя попытками. Watcher разделяет подготовку, исполнение, результат и сохранение Б; обработанная попытка не равна успеху задачи или сохранению Б. Кэш activation-UUID.json, индекс и flock размещены в Git. atomic_replace проверяет исходный текст перед os.replace, но гонка с редактором после проверки остаётся.*
### *Proposed changes for current vault*
*В [[Scenarios/001-mvp]] уточнить: чек-лист снимается, а не удаляется; статус заменяется по точному собственному фрагменту. В [[Conventions/Тикеты]] отделить создание дочернего тикета наблюдателем по сигналу пользователя от запрещённого инструкцией самостоятельного создания тикетов исполнителем. Предложения здесь; связанные заметки не изменены.*
### *Contradictions and non-implemented parts*
*Прежнее описание выше ошибочно называет fork отложенным: он реализован. Выделение ==, sudo, управление работающим исполнителем и настройка защиты remote остаются вне текущей реализации. Параллельные правки редактора после проверки текста не защищены полностью. Независимое пересоздание по stable и ссылкам не выполнялось; прохождение текущих тестов само по себе не доказывает полноту спецификации.*
