# obsta

*Poll an Obsidian vault for Markdown commands, assign monotonic SQLite ticket IDs, and dispatch tickets to Codex serially. The watcher records activation and agent result commits in Git.*

## Usage

*Для автоматического перезапуска запускайте `./Configs/obsta.sh` из корня vault (сам скрипт можно вызвать по абсолютному пути из любого каталога). Прямой запуск `python3 Sources/obsta.py` только возвращает код `75` при готовности обновления; повторный запуск выполняет shell-скрипт. `--once` выполняет один проход со стабилизацией файлов, `--self-test` запускает встроенные тесты. Уже работающую версию без этой логики нужно один раз вручную остановить после завершения тикета и запустить через `Configs/obsta.sh`.*

## Configuration

*Options: `--vault PATH`, `--interval SECONDS`, `--settle SECONDS`, and `--timeout SECONDS`. Defaults target the repository containing this script.*

## Логика работы

*При запуске скрипт проверяет, что указанный vault является корнем Git-репозитория, и что в нем есть инструкция агента. Экземпляр `Watcher` открывает SQLite-базу во временной директории; путь к базе зависит от абсолютного пути vault. Таблица `tickets` использует `INTEGER PRIMARY KEY AUTOINCREMENT`, поэтому назначенные идентификаторы монотонно растут между запусками.*

*`scan()` обходит Markdown-файлы, исключая служебные каталоги и файлы инструкции. Содержимое заметок хранится в памяти вместе со временем последнего изменения: команда обрабатывается, только если текст оставался неизменным не меньше `settle` секунд. За один проход запускается не более одной команды; после успеха состояние сканирования сбрасывается. Если `process()` возвращает `False`, `scan()` выбрасывает `RuntimeError`, и новые тикеты не запускаются.*

*`find_commands()` ищет жирные фрагменты и отмеченные пункты чек-листа. YAML frontmatter и огражденный код пропускаются, встроенный код маскируется, а команды внутри уже назначенных тикетов игнорируются. Команды обрабатываются в порядке их позиции в документе. Для жирного текста тикет охватывает только выделенный фрагмент; для чек-листа — пункт и его вложенные строки.*

*Перед запуском агента `process()` назначает ID, снимает сигнал жирного текста или отметку чек-листа, добавляет границы тикета и маркер ожидания. Изменение атомарно записывается в заметку и вместе со всеми текущими изменениями фиксируется Git-коммитом `(human)`. Затем инструкция и контекст тикета передаются процессу `codex exec`. Успех проверяется по маркеру завершения, новому коммиту `(agent)` и Git-статусу: допускаются только незастейдженные правки существующих Markdown-заметок вне активной заметки и файлов результата; они сохраняются без коммита. `process()` возвращает `True` и запоминает проверенный HEAD и пути результата. При ошибке он возвращает `False`, заменяет оставшийся маркер ожидания маркером ошибки и добавляет курсивное пояснение внутри тикета и запись в лог; watcher останавливается с кодом `1`.*

*В обычном режиме цикл вызывает `scan()` через заданный интервал. `--once` выполняет один проход с дополнительной задержкой для стабилизации файлов, а `--self-test` запускает встроенные модульные тесты. При старте сохраняется SHA-256 исходника. Перед каждым сканированием и после него `restart_requested()` сравнивает хеш; изменения Markdown сами по себе перезапуск не вызывают. При изменении Python требуется успешно проверенный предыдущий тикет, неизменный HEAD и допустимый Git-статус. Новая версия запускается тем же Python с `--self-test` в отдельном процессе с таймаутом 60 секунд. После проверки повторно проверяются хеш, HEAD и Git-статус. Успех приводит к выходу `75`; ошибка, таймаут или изменение исходника без успешного тикета — к остановке с кодом `1` и сообщением в журнале. Блокировка в системной временной директории не позволяет запустить второй watcher для того же vault; при завершении, включая выход `75`, `finally` закрывает SQLite, удаляет PID-файл и снимает блокировку. Обычный выход и Ctrl+C возвращают `0`.*

*## Публичные функции и методы*

*Ниже приведены интерфейсы, на которые опирается скрипт и его встроенные тесты. Функции с начальным подчёркиванием являются внутренними помощниками.*

```python
def find_commands(text: str) -> list[tuple[int, int, str, str]]: ...
def notes(root: Path) -> Iterator[Path]: ...
def git(root: Path, *args: str) -> str: ...
def atomic_replace(path: Path, before: str, after: str) -> None: ...
def ticket_boundary(text: str, start: int, end: int, kind: str) -> tuple[int, int]: ...
def allocate_id(db: sqlite3.Connection) -> int: ...

class Watcher:
     def __init__(self, root: Path, settle: float = 1.0, timeout: float = 1800, interval: float = 0.5, runner: Callable = subprocess.run) -> None: ...  init `Watcher.__init__` initializes the vault watcher, validates its Git root and agent instructions, then opens its per-vault SQLite ticket database.
    def close(self) -> None: ...
    def scan(self) -> bool: ...
    def process(self, path: Path, text: str, command: tuple[int, int, str, str]) -> bool: ...
    def restart_requested(self) -> bool: ...

def main() -> int: ...
```

*`find_commands` возвращает кортежи `(начало, конец, текст команды, тип сигнала)`, где тип — `bold` или `checklist`. `ticket_boundary` возвращает границы исходного текста, включаемого в тикет. `allocate_id` сохраняет запись в SQLite до возврата ID. `Watcher.scan` возвращает `True`, если обработал команду, иначе `False`, а при ошибке тикета выбрасывает `RuntimeError`; `process` активирует тикет, вызывает Codex и возвращает результат проверки. `restart_requested` возвращает `False` при прежнем исходнике, `True` после успешной проверки новой версии и выбрасывает исключение при отказе в перезапуске. `close` закрывает базу. `main` разбирает CLI-параметры и управляет жизненным циклом watcher; при ошибке параметров argparse завершает процесс с ненулевым кодом.*
