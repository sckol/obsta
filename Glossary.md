# Хранилище
Папка проекта, в которой хранятся как файлы Obsidian, так и исходные коды и другие файлы, нужные для разрабатываемого проекта
## Заметка
Markdown-файл в хранилище
# arc67
Набор архитектурных правил и шаблонов, предназначенной для контролируемой человеком разработки с помощью ИИ-агентов. См. [[Принципы arc67]]
# Тикет
*Задача в тексте с полным ID `KOL-1` (дочерний `KOL-1/1`) и границами в заметке; старые числовые ID сохраняются.* См. [[Тикеты]]
# Метки тикета
Значки, помечающие начало и конец [[Тикеты|тикета]]. См. [[Форматирование]]
# Ветка истории
*Общая локальная ветка `obsta-history`: watcher сохраняет А перед исполнителем и Б после результата, через отдельный индекс и условное продвижение ref, без смены HEAD. См. [[Использование Git]].*
# Агент-исполнитель
AI-агент, например, codex, которого вызывает obstagent для выполнения непосредственной работы.
# Сигнал активации
Действие пользователя в хранилище, которое активизирует работу obstagent, например, выделение жирным.
# obstagent
Скрипт, который работает в фоне и следит за содержанием хранилища, чтобы при поступлении сигнала от пользователя отработать его запрос, делая записи в git и вызывая агента-исполнителя.
# obsta-history пути
Пути, которые исключаются из отслеживания в обычных ветках гита, но которые тем не менее отслеживаются в ветке истории за счет специального комментария в файле .gitignore. См. [[Использование Git]].
# Статус тикета
Служебный текст перед закрывающей меткой [[Тикеты|тикета]], показывающий текущее состояние его обработки: начало работы (⏳), последнее рассуждение агента (💭), ответ агента (◇) или ошибку (❌). Выделяется курсивом и обновляется по мере обработки тикета. См. [[001-mvp]].
# Зачеркнутый
Текст, выделяемый в Markdown как `~~` с обеих сторон.
# Комментированный
Текст, выделяемый в Markdown как `%%` с обеих сторон.
# Отчеменный
Текст, выделяемый в Markdown как `==` с обеих сторон.
# sudo-режим агента
*Проектируемый режим расширенных прав; в текущем watcher не реализован. Расширение прав допускается явным разрешением активного запроса.*
# Watcher
Фоновый компонент obsta, реализованный в [[Sources/obstagent.py|obstagent.py]], который периодически опрашивает Markdown-файлы [[#Vault]], распознаёт команды пользователя и последовательно передаёт их агенту Codex.
