## Участники
- User
- Obsidian
- git
- Скрипт [[obsta.py]]
- Агент codex
## Процесс
1. Скрипт запущен в фоне следит за изменениями в документах Obsidian Vault
2. Пользователь заходит в Obsidian, делает правки в документах и оставляя ремарки комментированным форматированием (Ctrl+/ или пара двойных процентов `%%`).
3. Пользователь может пометить те части, которые он хотел бы, чтобы агент за него переписал, зачеркнутым.
4. Чтобы запустить агента, пользователь пишет комментарий, вопрос или команду прямо в тексте и выделяет его жирным. Либо выделяет отмеченным пункт чек-листа.
5. Скрипт ставит вокруг затронутого фрагмента метки тикета: `#<номер>🎬` в начале и `#<номер>🛑` в конце, а также снимает жирный и отмеченный чек-лист из исходного фрагмента. 
6. В качестве контекста агенту передается:
	1. Содержание тикета, в котором добавлена разметка согласно [[Agent Markdown]].
	2. Окружающий текст, в котором на месте тикета вставлен плейсхолдер, чтобы избежать дублирования, а также добавлена разметка согласно [[Agent Markdown]].
	3. Системная инструкция [[Conventions/Agent Instruction]].
7. Агент делает комит. В начале названия коммита нужно писать (human), название дается агентом по смыслу
8. Агент отрабатывает команду. Он может делать то же, что обычный агент с полным доступом за исключением правки и создания файлов vault'а напрямую. Агент может свободно править файлы, которые не поддерживаются Obsidian, но для которых созданы файлы с таким же именем и суффиксом `.md` в конце (например, можно править файл `xxx/yyy.py`, если в хранилище есть `xxx/yyy.py.md`). Для остальной правки он должен использовать специальные тулы, которые предоставляет obsta:
	1. Редактирование фрагмента вне тикета в соответствие с [[Agent Markdown]]
	2. Правка фрагментов внутри тикета в соответствие с [[Agent Markdown]]
	3. Добавление текста в конец тикета
	4. Постановка предложений новых задач в любой документ (нужно указать документ и абзац) в виде пунктов чек-листа
	5. Расширение зоны тикета (можно включать зачеркнутые и курсивные зоны до и после тикета, внутри включенных зон допускается обычный текст, пересечение с другими тикетами не допускается)
9. В процессе размышлений в конце тикета перед завершающей меткой скрипт вставляет последнее рассуждающее сообщение агента после эмозди 💭. Когда агент закончил работу, эта часть убирается. При сбое убираем эмодзи рассуждения и ставим ❌, после чего идет описание ошибки.
10. Агент должен вызвать тул, которые дает название текущей задачи. 
11. Система в конце делает коммит, начинающийся (agent), там же указывается ID тикета и название.
12. Пользователь может написать свой вопрос в том же тикете, тогда процесс повторяется, но контекст сессии передается. Таким образом, для пользователя тикеты являются "чатами", каждый со своим контекстом.

Точное значение каждого типа форматирования описано в документе [[Formatting]].
