## Problem
#KOL-29🎬 __Надо решить, как распростанять obstagent, чтобы можно было запустить его с помощью codex в любой директории. Сейчас такая просьбы например заканчивается тем, что агентские инструкции копируются в целевой репозиторий, а надо чтобы они брались из этого. Как лучше сделать?__

*◇ Я бы сделал пользовательский skill `obstagent`, связанный с этим репозиторием, и отделил установку программы от целевого vault.*

- *В этом репозитории хранить skill с инструкцией запуска. Подключить его один раз через симлинк `~/.agents/skills/obstagent` на соответствующую папку здесь. Тогда из любого проекта можно написать Codex: `$obstagent запусти для текущей директории`. [Официальная документация OpenAI](https://developers.openai.com/codex/skills/) подтверждает пользовательские skills и поддержку симлинков.*
- *Разделить два пути: каталог установки obsta — код и общие инструкции; целевой vault — заметки, настройки проекта и история. obstagent должен читать общую инструкцию из установки и передавать её исполнителю, сохраняя рабочую директорию исполнителя в целевом vault. Внешние ссылки инструкции разрешать относительно установки, проектные — относительно vault.*
- *В целевом репозитории хранить только его документы и настройки. Skill должен явно предписывать запуск установленного obstagent и запрещать копирование общих инструкций. Для будущего распространения другим пользователям эту интеграцию можно упаковать в plugin.*

*Сейчас одного skill недостаточно: проверка кода показала, что `--vault` уже есть, но `Agent Instruction.md` читается из целевого vault, а shell-обёртка выбирает vault по собственному расположению. Нужно устранить эти привязки и пересмотреть автообновление: установленная версия должна обновляться независимо от истории целевого проекта.*

*Первый шаг — локальный skill через симлинк и разделение путей установки/vault. Это сохранит этот репозиторий единственным источником общих инструкций. Предложение сверено с текущим кодом и документацией; запуск в другом vault не проверялся.*

__А как его распространять? Моя цель - чтобы человек мог легко поставить (пусть через агента) на свой компьютер obstagent и использовать для своего хранилища.__

*◇ Тогда я бы распространял obstagent как обычный Python-пакет с командой `obstagent`. Skill будет удобным способом управлять установленной программой через Codex.*

*Пользовательский сценарий: «Установи obstagent из этого репозитория и подключи к моему хранилищу». Агент устанавливает пакет в отдельное окружение через `uv tool install`, проверяет Git и доступность авторизованного Codex, настраивает хранилище и запускает наблюдатель.*

*Предлагаемый интерфейс, который ещё нужно реализовать:*

- *`obstagent init --vault /путь` — создать настройки с ником пользователя, проверить Git и подготовить хранилище без перезаписи существующих заметок.*
- *`obstagent doctor --vault /путь` — проверить зависимости, конфигурацию и доступ к исполнителю.*
- *`obstagent start --vault /путь` — запустить наблюдатель; отдельная настройка автозапуска позволит переживать закрытие терминала и перезагрузку.*
- *`obstagent install-skill` — подключить пользовательский skill для запуска из Codex в любом проекте.*

*Код, общие инструкции и необходимые справочные документы входят в пакет и выпускаются одной версией. Они собираются из этого репозитория; в пользовательское хранилище попадают только настройки и документы самого проекта. Установка не требует клонировать весь наш vault. Обновление пакета меняет общие инструкции сразу для всех подключённых хранилищ; работающие наблюдатели переходят на новую версию между заданиями.*

*Для первого релиза достаточно установки непосредственно из Git по фиксированному тегу через `uv tool install git+https://…@vX.Y.Z`. Позже можно опубликовать пакет в PyPI и сократить установку до `uv tool install obstagent`, если имя доступно. Plugin можно добавить позднее как канал установки интеграции с Codex.*

*Я бы начал с пакета, команд `init/doctor/start` и короткой инструкции установки для агента. По текущим файлам это ещё предстоит реализовать: сейчас поставляется скрипт, привязанный к структуре нашего vault; готового Python-пакета нет.*
