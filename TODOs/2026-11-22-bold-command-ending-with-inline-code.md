# *Жирная команда не распознаётся, если заканчивается inline code*

*Наблюдение: 22.11.2026, obsta, [[Sources/obstagent]]. Жирный запрос на выполнение задачи 4 заканчивался командой `python3 Sources/obstagent.py --self-test-full` в обратных кавычках непосредственно перед закрывающими двумя звёздочками. Заметка входила в область наблюдения, но `find_commands()` возвращал пустой список. Ошибки в журнале не было.*

*Минимальный пример — жирная фраза «Выполни» и inline code в конце:*

```markdown
**Выполни `command`**
```

*Причина: `visible()` заменяет inline code пробелами. Затем `bold_commands()` применяет к замаскированному тексту проверку `(?<!\s)` перед закрывающими звёздочками. Пробелы подставлены самим парсером, но воспринимаются как исходный пробел перед закрытием, поэтому корректное выделение отвергается. Если поставить точку вне обратных кавычек перед закрытием жирного, сигнал распознаётся. Такая пунктуация не должна быть необходима для запуска.*

- [ ] *Проверять границы жирного по исходному Markdown, сохраняя исключение самостоятельных сигналов внутри кода. Содержимое inline code внутри настоящей команды передавать исполнителю без изменений.*
- [ ] *При исправлении проверить команду с inline code в конце, в начале и в середине, выделение целиком вокруг inline code и несколько фрагментов кода; отдельно — inline code с несколькими обратными кавычками. Обычный код с двойными звёздочками внутри не должен запускать агента; настоящие пробелы на границах обрабатывать по принятому правилу Markdown.*

*В этом тикете зафиксирован дефект; код парсера не изменён.*
