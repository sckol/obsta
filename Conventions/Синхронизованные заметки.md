## Назначение
[[Glossary/Синхронизованная заметка|Синхронизованная заметка]] создаётся по шаблону [[Conventions/Templates/Synced note|Synced note]], после чего [[Glossary/obstagent|obstagent]] начинает двухстороннюю конфигурацию заметки с [[Конфигурационный файл|конфигурационным файлом]].

## Путь и содержимое
Путь рабочего файла задаётся в [[Frontmatter-свойство|frontmatter-свойстве]] Path: начальный / означает корень хранилища, иначе путь отсчитывается от папки заметки. Для Configs/gitignore.md значения /.gitignore и ../.gitignore эквивалентны. ~~Синхронизованная заметка связана с одним файлом; неоднозначный путь, несколько блоков в File content или несколько заметок для одного файла останавливают синхронизацию с диагностикой.~~ *~~Синхронизованная заметка связана с одним файлом. Неоднозначный путь или несколько заметок для одного файла останавливают синхронизацию с диагностикой.~~*

*~~В разделе File content файл можно хранить в одном кодовом блоке или разбить на несколько. Содержимое блоков соединяется в порядке их появления без добавления разделителей. Любой текст вне кодовых блоков в этом разделе считается комментарием и в файл не попадает.~~*
## Порядок работы
- если в синхронизованной заметке нет кодового блока в разделе File content или конфигурационного файла по указанному пути нет, то ничего не делает. Пользователь должен создать конфигурационный файл самостоятельно или отдав явную команду, например, через [[Чек-лист-задача|чек-лист-задачу]] (в шаблон уже встроена такая задача)
- ~~когда меняется кодовый блок внутри синхронизованной заметки, он меняет конфигурационный файл~~ *~~когда меняется объединённое содержимое кодовых блоков File content, obstagent обновляет конфигурационный файл~~*
- ~~когда меняется конфигурационный файл, он меняет кодовый блок внутри синхронизованной заметки~~ *~~когда меняется конфигурационный файл, obstagent обновляет содержимое кодовых блоков File content и сохраняет комментарии на месте~~*
- направление синхронизации определяется приоритетом: у файла с непустым содержимым (после удаления пробелов и переводов строк) приоритет больше, чем у  файла с пустым содержимым, дальнейший приоритет определяется временем модификации: более поздно измененный файл приоритетнее
- ~~В рамках синхронизации obstagent меняет только кодовый блок File content. Если правило приоритета не различает стороны (одинаковая непустота и время модификации), приоритет имеет кодовый блок заметки.~~ *~~В рамках синхронизации obstagent меняет в заметке только кодовые блоки File content. Для определения непустоты учитывается их объединённое содержимое. Если непустота и время модификации совпадают, приоритет имеет заметка.~~*
- ~~повреждение кодового блока останавливает синхронизацию~~ *~~повреждение любого кодового блока в File content останавливает синхронизацию~~*
- автоматическое обновление работает только при наличии обеих сторон; создание и удаление файла требуют явной команды. Перед записью повторно проверить Path и обе прочитанные версии; если они изменились, перечитать их и заново определить направление. Копировать текст буквально, включая завершающий перевод строки.
- *~~исчезновение файла или всех кодовых блоков File content не удаляет и не перезаписывает оставшуюся сторону~~*
- *~~при смене Path на существующий файл непустое объединённое содержимое блоков File content записывается в этот файл. Если оно пустое, содержимое файла переносится в блоки заметки с сохранением комментариев. Это правило имеет приоритет над временем модификации. Файл по старому Path сохраняется. Если файла по новому Path нет, файл не создаётся и блоки не меняются.~~*
