## Назначение
[[Glossary/Синхронизованная заметка|Синхронизованная заметка]] создаётся по шаблону [[Conventions/Templates/Synced note|Synced note]], после чего [[Glossary/obstagent|obstagent]] начинает двухстороннюю конфигурацию заметки с [[Конфигурационный файл|конфигурационным файлом]].

## Путь и содержимое
Путь рабочего файла задаётся в [[Frontmatter-свойство|frontmatter-свойстве]] Path: начальный / означает корень хранилища, иначе путь отсчитывается от папки заметки. Для Configs/gitignore.md значения /.gitignore и ../.gitignore эквивалентны. Синхронизованная заметка связана с одним файлом; неоднозначный путь, несколько блоков в File content или несколько заметок для одного файла останавливают синхронизацию с диагностикой.
## Порядок работы
- если в синхронизованной заметке нет кодового блока в разделе File content или конфигурационного файла по указанному пути нет, то ничего не делает. Пользователь должен создать конфигурационный файл самостоятельно или отдав явную команду, например, через [[Чек-лист-задача|чек-лист-задачу]] (в шаблон уже встроена такая задача)
- когда меняется кодовый блок внутри синхронизованной заметки, он меняет конфигурационный файл
- когда меняется конфигурационный файл, он меняет кодовый блок внутри синхронизованной заметки
- направление синхронизации определяется приоритетом: у файла с непустым содержимым (после удаления пробелов и переводов строк) приоритет больше, чем у  файла с пустым содержимым, дальнейший приоритет определяется временем модификации: более поздно измененный файл приоритетнее
- В рамках синхронизации obstagent меняет только кодовый блок File content. Если правило приоритета не различает стороны (одинаковая непустота и время модификации), приоритет имеет кодовый блок заметки.
- повреждение кодового блока останавливает синхронизацию
- автоматическое обновление работает только при наличии обеих сторон; создание и удаление файла требуют явной команды. Перед записью повторно проверить Path и обе прочитанные версии; если они изменились, перечитать их и заново определить направление. Копировать текст буквально, включая завершающий перевод строки.
- *исчезновение файла или кодового блока не удаляет и не перезаписывает оставшуюся сторону
- при смене Path на существующий файл содержимое корректного кодового блока заметки записывается в этот файл, если кодовый блок непустой, в противном случае в кодовый блок записывается содержимое файлы; это правило имеет приоритет над временем модификации. Сам кодовый блок и файл по старому Path не меняются. Если файла по новому Path нет, ничего не создавать и блок не менять*

## Кэширование
- *Для каждой связи obstagent может держать хеш точного содержимого кодового блока только в памяти процесса. Правки пояснений и обсуждений при неизменном блоке не вызывают запись в конфигурационный файл. Изменения самого конфигурационного файла обрабатываются независимо от этого хеша. После успешного копирования хеш обновляется; совпадающее содержимое не перезаписывается, собственные записи не вызывают обратное копирование по кругу.*
- *После запуска кэш для связи отсутствует: направление первоначального согласования определяется указанным выше правилом приоритета. Смена Path обрабатывается отдельно по разделу «Удаление и перенос» и сбрасывает кэш связи; после записи блока в файл хеш блока обновляется. Хеш — оптимизация во время работы, на диск он не сохраняется. Синхронизация не создаёт архивов старых версий или резервных копий.*
