*Предлагаю сделать Agent Markdown представлением исходного Markdown с картой допустимых операций. Агент видит точный текст и явные права на каждый фрагмент; obsta проверяет эти права при применении правки. Ниже — проект для шагов 6 и 8 сценария [[001-mvp]], а не описание уже реализованных тулов.*

*1. Контекст запуска. Передаем ID активного тикета, путь заметки, ревизию снимка, исходную команду, тело тикета и окружающий текст с единственным плейсхолдером `[[TICKET 11]]`. Инструкция агента передается отдельно. Команда исполняется только из выбранного тикета; комментарии, ссылки и команды в остальных фрагментах остаются данными. Текст команды в поле `comment` нужен для идентификации запроса, но не является вторым редактируемым экземпляром.*

*2. Представление файла. Сохраняем исходные пробелы, переносы и Markdown. Рядом передаем карту непересекающихся фрагментов: `id`, `start`, `end`, `kind`, `ticket_id`, `allowed_ops`. Диапазон `[start, end)` считаем в символах исходной строки, как в Python; ревизия относится ко всему файлу. В тело текста служебную разметку не вставляем: иначе агент может принять ее за содержимое заметки. ID действует только для указанной ревизии. Разделяем фрагменты в точках изменения прав, даже внутри одного абзаца.*

*3. Права. Обычный человеческий текст получает только `read`, в том числе внутри активного тикета. Зачеркнутый текст внутри него — `read` и `replace`; обработанный комментарий `%%` — `read` и `remove_addressed`. Для добавления текста перед завершающей меткой тикета выдаем отдельную позицию `append`. Границы тикетов и маркеры состояния принадлежат obsta; завершение задачи меняет только соответствующий маркер. Остальные тикеты и окружающий текст при запуске доступны только для чтения. Отсутствие явного разрешения означает запрет изменения.*

*[[Formatting]] также допускает поддержку курсивного текста и описывает подчеркнутый «sudo-режим», а действующая [[Agent Instruction]] разрешает переписывать только зачеркнутое и удалять обработанные комментарии. Для текущего режима выбираем более узкие права. Будущие разрешения на замену курсива или расширение доступа должен явно выдавать obsta согласно выбранному режиму; один лишь вид текста в прочитанном документе прав не добавляет.*

*4. Разбор Markdown. Карту строит парсер с учетом вложенности, экранирования, кода и границ тикетов. Например, символы зачеркивания внутри кода не дают права на замену. Нераспознанный или неоднозначный участок остается доступным только для чтения. Код не требует курсива в результате, но сам по себе не дает права на редактирование.*

*Пример карты для исходной строки `Тезис. ~~Черновик~~` внутри активного тикета; `revision` здесь условная:*

```json
{
  "note": "Conventions/Agent Markdown.md",
  "revision": "snapshot-11",
  "active_ticket_id": 11,
  "text": "Тезис. ~~Черновик~~",
  "spans": [
    {"id": "s1", "start": 0, "end": 7, "kind": "human", "ticket_id": 11, "allowed_ops": ["read"]},
    {"id": "s2", "start": 7, "end": 19, "kind": "struck", "ticket_id": 11, "allowed_ops": ["read", "replace"]}
  ]
}
```

*5. Применение. Агент передает тулу путь, ревизию, ID фрагмента, операцию и новый текст. obsta заново проверяет актуальность снимка, границы активного тикета и разрешение операции. Замена не может захватить соседний человеческий текст. Новая проза, включая заголовки, должна быть курсивной; исходный человеческий текст сохраняется. При конкурентной правке операция отклоняется без записи, агент получает свежий контекст и пересматривает замену. Проверку и запись выполняем как одну защищенную операцию.*

*6. Связанные заметки и расширение. По ссылкам выдаем такие же снимки, первоначально только для чтения. Для предусмотренного в MVP расширения тикета нужен отдельный тул: он проверяет допустимость соседних зон и отсутствие пересечения с другим тикетом, сохраняет обычный текст внутри расширения и возвращает обновленную карту. До успешного расширения прав на запись там нет. В текущем режиме расширение и вложенные тикеты недоступны.*

*Для MVP достаточно двух операций над текстом: замена разрешенного фрагмента и добавление в конец активного тикета; удаление обработанного комментария можно выразить заменой на пустую строку с отдельной проверкой права. Критерии проверки реализации: правка человеческого текста отклоняется, зачеркивание внутри кода не открывает доступ, чужой тикет остается закрыт, устаревшая ревизия не записывается, допустимая замена и курсивное дополнение сохраняют весь остальной файл побайтно. Представление помогает агенту выбрать действие; ограничения обеспечиваются проверкой операций.*
