*Актуальный режим — локальная `obsta-history`, см. [[Использование Git]]. [[obstagent]] последовательно сохраняет А, запускает исполнителя, записывает результат и сохраняет Б. Ошибки Git и тикета диагностируются; наблюдение продолжается. Диалоги ниже описывают прежние версии.*

*Запуск из корня vault:*

```sh
python3 Sources/obstagent.py --self-test
sh -n Sources/obstagent.sh
./Sources/obstagent.sh
```

*Обёртка определяет vault по своему расположению и повторяет запуск только после выхода `75`. При прямом запуске `python3 Sources/obstagent.py` этот код требует внешнего повторного запуска. obstagent хранит индекс, кэш активаций, PID/идентичность исполнителя и блокировку внутри служебной области Git. Старую SQLite не читает, не мигрирует и не удаляет.*

*Обновление Python проверяется между запросами: активация учтена снимком Б, хеш исходника совпадает с сохранённым в истории, новая версия проходит `--self-test` за 60 секунд, хеш проверяется повторно. Чистый HEAD не требуется. При провале старая загруженная версия продолжает наблюдение; тот же непрошедший хеш повторно не тестируется. Изменения shell и окружения требуют отдельного перезапуска между запросами.*

*После аварии obstagent сопоставляет А/Б по UUID. Завершённое не запускает повторно. Если исполнитель ещё жив и его идентичность совпала, ждёт его завершения. Неизвестный исход требует явного продолжения; сохранённый результат позволяет поздний Б с соответствующими метаданными. LaunchAgent и защита remote в этот переход не входят.*
